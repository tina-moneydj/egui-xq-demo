# egui 拍板前的四項驗證清單（2026-10-25）

效能數據 egui 幾乎都贏或持平，拍板前再確認 egui 四個比較弱的地方。每項寫清楚**怎麼驗、怎樣算過、雲端驗了什麼、實機還要做什麼**。
規則：**四項都過 → 選 egui**；有一項沒過，先看是不是我們自己程式能修，再決定。

> **2026-10-26 判定：四項都過 → 選 egui。** 第 4 項的條件（先定好面板寫法）照第 4 節做。

驗證用的小程式：[`examples/probe.rs`](../examples/probe.rs)（獨立範例，不影響主程式與壓測），三個分頁對應第 1～3 項。
網頁並排範例：[`examples/web-multi/tokens.html`](../examples/web-multi/tokens.html)（第 2 項）。截圖與原始紀錄：[`docs/bench/2026-10-25-egui-weakness/`](bench/2026-10-25-egui-weakness/)。

## 結論先看

| 項目 | 雲端（Linux、無 GPU） | 實機 | 目前判斷 |
|---|---|---|---|
| 1. 中文字與輸入法 | ✅ 注音、倉頡、選字、邊跳價邊打字都正常，和 GPUI 同樣結果；字的清晰度和 GPUI 肉眼幾乎一樣 | ✅ Tina 實機跑 probe，2026-10-26 回報「都蠻正常」 | **過** |
| 2. 視覺（降標準） | ✅ 只用 token 畫的報價卡、下單匣，深淺色都乾淨一致；**egui 元件和網頁元件並排，背景、標頭、選取列顏色逐像素相同，列高、字級、字型一樣** | 不需要（實機只看字，併入第 1 項） | 過 |
| 3. 多視窗 | ✅ 開 8 個原生視窗、各自關閉（關閉鈕、Ctrl+W）、各自對話框、面板搬到另一個視窗再搬回來都正常 | ✅ 同上（probe 多視窗頁） | **過** |
| 4. 大型程式結構 | ⚠️ 同樣功能 egui 版程式碼少 25%（7,680 vs 10,331 行）；結構風險有 4 點，都有固定寫法可以規範（見第 4 節） | 不需要 | 有條件過：要先定好面板寫法 |

雲端找到、要記住的三件事：

1. **egui 快捷鍵要用 `consume_shortcut`**，不要用 `i.modifiers.command && key_pressed(..)`。視窗閒置時，按下和放開會擠在同一幀，後者會漏掉（實測 8 個視窗時 Ctrl+W 三次都沒反應，改寫後三次都成功）。主程式現有寫法（`chart.rs` 看事件本身的修飾鍵）沒有這個問題。
2. **Linux 上 egui 的選字窗會蓋住輸入框下半部約 10 px**（GPUI 在框下方）。原因是 winit 在 X11 只送游標左上角給輸入法、不送高度（`winit-0.30 x11/window.rs set_ime_cursor_area`）。Windows／Mac 的 winit 會送整個游標框，要在實機確認。只影響 Linux。
3. **egui「立即」型子視窗是一起重畫的**：任一個視窗要重畫，所有子視窗都跟著畫一次（實測 8 個視窗的幀數完全相同）。看盤時每個視窗本來就都在跳價，影響不大；如果之後有大量靜態視窗，要改用「延後」型子視窗（`show_viewport_deferred`，各自重畫，但狀態要能跨執行緒共用）。

## 怎麼跑驗證小程式

```bash
cargo run --release --example probe                    # 預設第 1 頁
XQ_PROBE_TAB=multi XQ_PROBE_WINDOWS=8 cargo run --release --example probe   # 直接開 8 個子視窗
XQ_IME_LOG=1 cargo run --release --example probe       # 輸入法事件印到終端機
```

不想裝 Rust：main 合併後，GitHub 的 **probe-latest** 預發行版會有編好的 `egui-probe-windows.zip`、`egui-probe-mac-arm64.zip`（[`probe.yml`](../.github/workflows/probe.yml) 自動產生）。
Windows 第一次開會跳 SmartScreen，按「其他資訊 → 仍要執行」；Mac 解壓後先在終端機跑 `xattr -d com.apple.quarantine probe`。

字型：預設用網頁版內嵌的 Noto Sans TC 子集（三個平台同一份，方便對照），可在第 1 頁切「系統字型」。
Windows 預設找微軟正黑體；Mac 新版的蘋方在系統資料夾深處，要指定：
`XQ_CJK_FONT="$(find /System/Library/AssetsV2 -name PingFang.ttc | head -1)" XQ_CJK_FONT_INDEX=2 ./probe`。

## 1. 中文字清晰度與輸入法

**驗證方法**

- 字：第 1 頁列出 token 的 5 個字級（10～15 px）加 16、20 px 的股名與數字，深底、淺底各一；可切內嵌字型／系統字型、hinting 開關、縮放 100～200%。主程式的報價表和 GPUI 版同位置截圖對照。
- 輸入法：搜尋框、多行框。注音打「台積電」（大千：`w96 ru␣ 2u04`），用方向鍵叫出候選、選字；倉頡打「台積電」（`ir hdqmc mbwu`，倉頡五代）。主程式搜尋框在**邊跳價邊打字**時做同樣的事，再按 Enter 跳到該檔。

**通過標準**

- 12 px（報價表字級）以上，股名每個字的筆畫可以分辨，不比 GPUI 版糊；數字等寬、對齊。
- 組字中的字畫在框裡、有底線，表格跳價不會打斷組字；選字窗貼在游標下方、不蓋住正在打的字。
- 送字後沒有重複字、沒有掉字；送字用的 Enter 不會被當成「跳轉」；Backspace／Esc 只動組字中的字。
- 失焦再回來可以繼續打。

**雲端結果（Linux X11、fcitx5 新酷音＋倉頡五代）**

| 項目 | egui | GPUI | 證據 |
|---|---|---|---|
| 注音組字、底線、游標 | ✅ | ✅ | `1-ime-egui-main.png`、`1-ime-gpui-main.png` |
| 邊跳價（每秒 200 筆）邊打字 | ✅ 組字不中斷 | ✅ | 同上 |
| 方向鍵叫候選、選字 | ✅（選「積」後送出「台積電」） | ✅ | `1-ime-candidates.png` |
| 倉頡 | ✅ 每個字送一次，「台」「台積」「台積電」搜尋結果逐步縮小 | ✅ | `1-ime-cangjie.png` |
| 送字 Enter 不誤跳；再按 Enter 跳到 2330 | ✅ | ✅ | 主程式 log：`Commit("台積電")` → `query="台積電" matches=["2330"]` |
| 重複字／掉字 | 沒有 | 沒有 | `[ime]` log |
| 選字窗位置 | ⚠️ 蓋住框的下半部約 10 px（winit X11 限制，見上） | 在框下方 | `1-ime-candidates.png` |
| 失焦再回來 | ⚠️ 回來時輸入法變回英文，要再按一次切換鍵 | 未測 | fcitx 的每個輸入框各自記狀態；Windows／Mac 行為不同，要實機看 |
| 字的清晰度（12 px 報價表） | 肉眼幾乎一樣；egui 筆畫略粗一點（筆畫像素佔比 9.9% vs 9.2%） | | `1-font-egui-vs-gpui.png`（上 egui、下 GPUI，放大 2 倍） |
| 10～11 px | 筆畫多的字（聯、灣、鴻）擠在一起，GPUI 也一樣（字太小，不是框架問題） | | `1-cjk-samples-zoom.png` |

附帶發現：

- egui 0.37 的字是 skrifa 外框＋自己的點陣化，有 hinting（預設開）；**只有灰階反鋸齒，沒有 Windows ClearType 那種彩色次像素**。Windows 上和 GPUI（DirectWrite）比最可能看出差別，是實機重點。
- egui **沒有字重**：粗體要另外載一個粗體字型檔當一個字型家族（小程式已示範）。
- 網頁版內嵌的 Noto Sans TC **子集**缺少罕用字（龘、齉、爨、驫、鑫顯示空白），換系統字型就正常。是字型子集範圍的問題，不是 egui；正式版要定子集範圍或改用系統字型。
- iOS 已知：iOS 26 的蘋方 egui 畫不出來（`bench/ios/README.md`），改用冬青黑體＋Noto 補字。

**實機步驟（Windows、Mac 各做一次，約 20 分鐘）**

1. 開 probe 第 1 頁，切「系統字型」，Windows 在 100%、125%、150% 顯示縮放各截一張；Mac 用內建螢幕截一張。和 GPUI 主程式報價表同字級比對，回報「哪一個比較清楚／一樣」。
2. 搜尋框用**微軟注音**（Windows）／**注音**（Mac）打「台積電」，用方向鍵選字；再用**倉頡**（Windows 倉頡、Mac 倉頡）打一次。看：底線、選字窗位置、有無重複或掉字。
3. 打到一半點框外再點回來，看組字有沒有正確結束、輸入法狀態有沒有保留。
4. 主程式 `XQ_SEARCH=1` 開搜尋框，接行情，邊跳價邊打「台積電」→ Enter → Enter，看會不會跳到 2330。
5. 有問題的截圖＋`XQ_IME_LOG=1` 的輸出貼回來。

**通過條件**：步驟 1 不比 GPUI 差；步驟 2～4 沒有掉字、重複字、誤跳；選字窗不蓋到正在打的字。

## 2. 視覺可以做到多精緻（降標準）

XQ 的人設是效能優先、不需要特別效果，要漂亮的元件可以用網頁寫。所以標準改成兩條：

**通過標準**

1. egui 元件只用設計 token，就能做到乾淨、一致：圓角、細線、hover／按下／焦點／停用狀態、淡入淡出提示、深淺色切換。
2. **egui 元件和網頁元件放在同一頁時，顏色、字型、間距讀同一份 token，看起來一致**（同一個位置的顏色逐像素相同，列高、字級相同）。

**雲端結果**

- ✅ 第 2 頁的報價卡、下單匣全部只用 token：`2-components-dark-light.png`（上深色、下淺色，F8 切換）。
- ✅ `tokens.html`：左邊 egui 報價表（canvas）、右邊一般 HTML 報價表和下單匣（只寫 `var(--xq-…)`，不寫色碼）。token 由 wasm 的 `tokens_css()` 在載入時產生，**和 egui 元件用的是同一份 `xq_tokens::t()`**；網頁字型也和 egui 編進 wasm 的是同一份檔案。無頭 Chromium 量測（`2-tokens-results.json`）：

  | 位置 | egui | HTML | 一樣？ |
  |---|---|---|---|
  | 標頭底色 | #171c26 | #171c26 | ✅ |
  | 選取列底色 | #1e3a5f | #1e3a5f | ✅ |
  | 面板底色 | #10141c | #10141c | ✅ |
  | 標頭高／欄位標頭高／列高 | 26／22／22 px（token） | 26／22／22 px | ✅ |
  | 字型、字級 | Noto Sans TC 子集 12 px | 同一份檔案 12 px | ✅ |

  截圖：`2-tokens-egui-vs-html.png`。這也就是選型文件「跨平台設計對焦」第 5 節「html 面板也照這套：平台層把 token 提供給面板」的做法：**平台層只要在頁面放一段 token CSS，AI 寫的面板只用 `var(--xq-…)`**。

**要注意（不影響過關）**

- egui 自己的預設配色（例如淺色主題的輸入框底色）不在 token 裡，要在 `apply_visuals` 把 egui `Visuals` 的欄位都對到 token，不然會露出 egui 預設色（第 2 頁淺色的輸入框就和底色太接近）。
- 主程式報價表還有幾個寫死的值（代號／名稱欄 12 px、壓力按鈕圓角 2 px），盤點時一起收進 token。
- egui 做不到的：背景模糊（毛玻璃）、CSS 那種任意漸層與複雜排版、字重以外的字型特性（例如 OpenType 等寬數字開關）。XQ 人設用不到；真的要就用網頁元件。

## 3. 多視窗

**驗證方法**：第 3 頁可以開 1～16 個原生視窗（`XQ_PROBE_WINDOWS=N` 直接開），每個視窗有自己的對話框、右下角的選單與提示（看碰到視窗邊緣會怎樣）、Ctrl+W 關自己；主視窗的面板可以「搬到新視窗」、再「搬回主視窗」，狀態保留。主程式另外已有 `XQ_WINDOWS=N`（真的跳價的多視窗壓測，實機數據見 README）。

**通過標準**

- 開 8 個視窗，每個都能各自操作、各自關閉，關一個不會關到別的或整個程式。
- 視窗內的選單、提示、對話框正常；碰到視窗邊緣會自己往內移，不會被切掉。
- 面板可以在視窗之間搬移，狀態不掉。
- 實機：雙螢幕不同縮放（例如 100% ＋ 150%）之間拖視窗，字和版面跟著換縮放、不糊；8 個視窗跳價時 CPU 不失控。

**雲端結果**

| 項目 | 結果 | 證據 |
|---|---|---|
| 開 8 個視窗 | ✅ 依序在 10～81 ms 內畫出第一幀；8 個視窗時小程式 RSS 147 MB | `3-eight-windows.png`、`3-multiwindow.log` |
| 各自關閉 | ✅ 視窗關閉鈕、Ctrl+W 各關掉指定那個，其他視窗和主視窗照常 | log：`close 2`、`close 5`、`close 7`、`close 3` |
| 選單、提示碰到邊緣 | ✅ 自動往視窗內移，不會被切掉；但**不能超出視窗**（GPUI 也一樣，兩者的浮層都畫在視窗裡） | `3-menu-tooltip-edge.png` |
| 每個視窗自己的對話框 | ✅ | `3-modal.png` |
| 面板搬到新視窗（取代拖出分頁） | ✅ 按鈕次數、輸入的文字都保留 | `3-panel-moved.png` |
| 拖曳分頁到視窗外自動開新視窗 | 沒有現成功能，要自己做（偵測拖出視窗 → 開新視窗 → 搬狀態）。GPUI 也沒有現成的 | — |
| 子視窗重畫 | ⚠️ 立即型子視窗一起重畫（見上） | 8 個視窗幀數相同 |

**實機步驟（Windows 雙螢幕那台）**

1. `XQ_PROBE_TAB=multi XQ_PROBE_WINDOWS=8 probe`：逐一關閉幾個視窗（關閉鈕＋Ctrl+W，Mac 是 ⌘W），確認其他的沒事。
2. 把一個子視窗從 100% 螢幕拖到另一個螢幕（如果兩個螢幕縮放不同，先在 Windows 設定把其中一個改成 125% 或 150%），看字有沒有糊、版面大小對不對。
3. 主程式 `XQ_WINDOWS=8` 接 `xq-tickgen --rate 10000`，看工作管理員 CPU 和每個視窗的 FPS（已有壓測包的 4 視窗數據，這步只是加到 8 個）。

## 4. 大型程式好不好維護

egui 每幀重畫整個畫面，風險不在效能（已量過），而在程式**結構**：狀態放哪、面板之間怎麼溝通、怎麼避免每幀重算。

**現況量測（同樣功能的兩個 demo）**

| | egui | GPUI |
|---|---:|---:|
| `src/` 總行數 | 7,680 | 10,331 |
| 函式數 | 392 | 535 |
| 超過 100 行的函式 | 8 | 12 |
| 最長的函式 | 168 行（`chart.rs build_plot`） | 200 行（`chart.rs paint_plot`） |
| 新增一個面板（成交明細範例）動到 main.rs 的地方 | 17 處提到 tape | 16 處 |

同樣功能 egui 少約 25%，主要是 GPUI 的 `Entity`／`Context` 樣板和 `render` 建元素樹的程式比較長。新增面板要動的地方兩邊差不多。

**egui 版要先規範的 4 件事（看主程式現有寫法歸納）**

1. **狀態集中、借用要拆開**：主程式 `Terminal` 有約 40 個欄位，畫面函式靠 `View<'_>` 一次借好幾個 `&mut`，多視窗時用 `let Terminal { peers, table, .. } = self` 拆借。面板一多會越來越難寫。
   → 規範：每個面板一個 struct（狀態＋快取），App 只持有 `Vec<Box<dyn Panel>>` 和共用資料（行情快照）。
2. **面板之間溝通**：現在 `draw()` 回傳 `(Option<Period>, Option<String>)`，面板多了會變成一長串回傳值。
   → 規範：面板只回傳「命令」（`enum Cmd { SwitchSymbol(..), OpenWindow(..), .. }`），每幀結束時 App 統一處理。這就是 GPUI `EventEmitter` 的對應做法。
3. **每幀重算的成本**：egui 每幀都呼叫畫面程式，貴的東西一定要快取。主程式已有固定做法：`gfx::Sink` 組好 Mesh，用 Key（可見範圍、選取列、字型版本…）判斷要不要重組（報價表、成交明細、走勢圖三層都是）。
   → 規範：新面板照 `tick_tape.rs` 的寫法，畫面函式裡只做「比對 Key → 用快取」。code review 檢查有沒有在畫面函式裡 `format!` 全部列、排序、配置大陣列。
4. **id 與多視窗**：egui 的元件狀態用 id 存，同一個面板開在兩個視窗會撞 id。主程式用 `ui.push_id(視窗 id, ..)` 解決。快捷鍵用 `consume_shortcut`（見上）。
   → 規範：面板的 `ui()` 一律包在 `push_id(面板 id)` 裡；快捷鍵統一一個表，不要各面板自己比按鍵。

**面板介面草稿**

```rust
trait Panel {
    fn id(&self) -> PanelId;
    /// 每幀最多一次，對應 GPUI 版 Terminal::apply_feed（AGENTS.md 規則 3）
    fn apply_feed(&mut self, inbox: &bridge::Inbox);
    /// 只畫、只回命令；貴的東西用 Key 快取（規則 3）
    fn ui(&mut self, ui: &mut egui::Ui, cmds: &mut Vec<Cmd>);
    /// 存檔用（#[serde(default)]，AGENTS.md 規則 12）
    fn save(&self) -> serde_json::Value;
}
```

**驗證方法與通過標準（之後做，約 2 天）**

1. 照上面的介面把主程式的報價表、走勢圖、成交明細改成 `Panel`，`Terminal` 只剩共用資料＋面板清單＋命令處理。
2. 用新介面加一個新面板（建議「報價卡」），量：動到幾個檔案、main.rs 改幾行。
3. 壓測數字（`apply_feed`、每幀組圖時間、RSS）不變差。

通過：新增一個面板只動「面板自己的檔案＋註冊一行」；`Terminal` 欄位數減半；壓測不退步。

**測試**：egui 有官方的介面測試工具 `egui_kittest`（無頭跑、可截圖比對、可模擬點擊與鍵盤），可以補上 GPUI `TestAppContext` 那種介面測試；要加相依需架構負責人同意，先列為建議。
